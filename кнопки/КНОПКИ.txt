Кнопки лежат в папке  zxc\кнопки\  , а работают всегда над репозиторием
этажом выше (zxc). Двойной клик по .bat - и всё.

Чтобы кнопка была под рукой: ПКМ по .bat ->
"Отправить" -> "Рабочий стол (создать ярлык)".


  connect.bat  - поднимает ssh-agent, кладёт в него ключ ~/.ssh/id_rsa,
                 проверяет связь с github.com:Kredos9107/zxc
                 и открывает Git Bash прямо в папке репозитория.
                 Логика внутри - в connect.sh, там же можно править.

  push.bat     - показывает что изменилось, спрашивает комментарий
                 (Enter = автоматический "update <дата> <время>"),
                 делает add -A + commit + push текущей ветки.
                 Если GitHub отказал - объясняет почему:
                   * файл больше 100 МБ -> подскажет git rm --cached
                   * на сервере есть чужие коммиты -> предложит rebase
                   * ключ не принят -> запусти connect.bat

  pull.bat     - забирает изменения с GitHub (pull --rebase).


ПРИНУДИТЕЛЬНЫЙ ПУЛЛ
-------------------
Это режим "выкинуть всё локальное и взять то, что лежит на GitHub".
Нужен, когда на устройстве намешано и проще начать с чистой версии.

Попасть в него можно тремя путями:

  1. запустить  pull-force.bat
  2. запустить  pull.bat  , когда есть незакоммиченные правки -
     он спросит: [1] отмена / [2] FORCE
  3. если при обычном pull начался конфликт - он тоже предложит FORCE

В любом случае придётся ВРУЧНУЮ напечатать слово  FORCE  заглавными.
Просто Enter или что угодно другое = отмена, ничего не произойдёт.

Что он делает:
    git fetch origin
    git branch -f backup-<sha>      <- если есть локальные коммиты
    git stash push -u               <- если есть незакоммиченные правки
    git reset --hard origin/<ветка>
    git clean -fd                   <- удаляет с диска файлы, которых нет в репе

Страховка (не рассчитывай на неё, но она есть):
    git log backup-<sha>     - посмотреть выкинутые коммиты
    git stash list           - посмотреть выкинутые правки
    git stash pop            - вернуть их обратно
    git branch -D backup-... - удалить страховочную ветку, когда не нужна


ПРО КЛЮЧИ И PAGEANT
-------------------
Один и тот же ed25519-ключ лежит на диске в двух форматах:

  C:\Users\<имя>\.ssh\id_rsa            - формат OpenSSH, им пользуется git
  C:\Users\<имя>\Desktop\PuTTY\ключ.ppk - формат PuTTY, им пользуется pageant

Пароля нет ни на том, ни на другом.

git for Windows ходит по ssh через свой OpenSSH
(C:\Program Files\Git\usr\bin\ssh.exe) и pageant НЕ ВИДИТ - это
агент протокола PuTTY, с ним умеют говорить только plink/putty/WinSCP.
OpenSSH просто читает id_rsa с диска напрямую, а раз пароля нет -
агент ему вообще не нужен.

Поэтому push/pull работают и без pageant, и без ssh-agent.
Проверка: закрой pageant и выполни в Git Bash  git ls-remote origin

pageant нужен, только если ты ходишь putty/plink'ом на какой-то сервер,
или если специально заставить git ходить через plink:
    setx GIT_SSH "C:\Users\<имя>\Desktop\PuTTY\plink.exe"
Сейчас GIT_SSH не выставлена, и трогать её не нужно.


ДВЕ ЛОВУШКИ, КОТОРЫЕ КНОПКИ ОБХОДЯТ САМИ
---------------------------------------
1. "The authenticity of host 'github.com' can't be established"
   при запуске .bat двойным кликом.
   Git'овский ssh, запущенный не из Git Bash, портит кириллическое имя
   папки пользователя (Данил) и ищет ключ в несуществующей папке.
   push.bat и pull.bat поэтому сами указывают ssh путь к ключу через
   короткое ASCII-имя папки (вида C:\Users\486B~1). В Git Bash такой
   проблемы нет. Если это окно всё же появилось - НЕ отвечай yes,
   закрой (Ctrl+C) и проверь, что кнопки свежие (git pull).

2. Переименование файла, где меняется ТОЛЬКО регистр букв
   (Анмех.pdf -> АНМЕХ.pdf).
   Windows считает это одним файлом, git для кириллицы - двумя,
   и пулл на другом компе падает с
   "untracked working tree files would be overwritten".
   pull.bat это распознаёт и чинит сам через fix-case.sh: убирает
   старое имя (только если содержимое побайтово совпадает с GitHub)
   и повторяет пулл. Если повтор не удался - возвращает всё назад.
   Лучше так не переименовывать: меняй имя целиком или через
   промежуточное (Анмех.pdf -> tmp.pdf -> АНМЕХ.pdf, два коммита).

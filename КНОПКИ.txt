Три кнопки (двойной клик по файлу в папке репозитория).
Чтобы кнопка была на рабочем столе: ПКМ по .bat ->
"Отправить" -> "Рабочий стол (создать ярлык)".

  connect.bat  - поднимает ssh-agent, кладёт в него ключ ~/.ssh/id_rsa,
                 проверяет связь с github.com:Kredos9107/zxc
                 и открывает Git Bash прямо в этой папке.
                 Логика внутри - в connect.sh, там же можно править.

  push.bat     - показывает что изменилось, спрашивает комментарий
                 (Enter = автоматический "update <дата> <время>"),
                 делает add -A + commit + push текущей ветки.
                 Если GitHub отказал - объясняет почему:
                   * файл больше 100 МБ -> подскажет git rm --cached
                   * на сервере есть чужие коммиты -> предложит rebase
                   * ключ не принят -> запусти connect.bat

  pull.bat     - забирает изменения с GitHub (pull --rebase).
                 Если есть незакоммиченные правки - откажется работать
                 и попросит сначала запустить push.bat.


ПРО КЛЮЧИ И PAGEANT
-------------------
Один и тот же ed25519-ключ лежит на диске в двух форматах:

  C:\Users\<имя>\.ssh\id_rsa          - формат OpenSSH, им пользуется git
  C:\Users\<имя>\Desktop\PuTTY\ключ.ppk - формат PuTTY, им пользуется pageant

Пароля нет ни на том, ни на другом.

git for Windows ходит по ssh через свой OpenSSH
(C:\Program Files\Git\usr\bin\ssh.exe) и pageant НЕ ВИДИТ - это
агент протокола PuTTY, с ним умеют говорить только plink/putty/WinSCP.
OpenSSH просто читает id_rsa с диска напрямую, а раз пароля нет -
агент ему вообще не нужен.

Поэтому push/pull работают и без pageant, и без ssh-agent.
Проверка: закрой pageant и выполни в Git Bash  git ls-remote origin

pageant нужен, только если ты ходишь putty/plink'ом на какой-то сервер,
или если специально заставить git ходить через plink:
    setx GIT_SSH "C:\Users\<имя>\Desktop\PuTTY\plink.exe"
Сейчас GIT_SSH не выставлена, и трогать её не нужно.
